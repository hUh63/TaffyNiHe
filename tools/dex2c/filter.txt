# Dex2C (dcc) method-selection table, consumed by the "Dex2C 加固发布 APK
# (Harden release APKs with Dex2C)" step in .github/workflows/build-multiabi.yml.
#
# Syntax (amimo/dcc, MethodFilter._load_filter_configure):
#   <regex>    compile matching methods
#   !<regex>   never compile matching methods
#   =<name>    exact full match
#   #...       comment
# A regex is re.search()ed against the concatenation
# "<class descriptor><method name><method descriptor>", e.g.
#   Lcom/soreverse/mcp/core/BackupCrypto;encrypt(Ljava/lang/String;Ljava/lang/String;)[B

# Constructors and static initializers are never valid targets: the
# System.loadLibrary("nc") call that makes the converted methods resolvable
# lives in BackupCrypto's <clinit>, so converting it would be self-defeating.
!<clinit|init>

# Scope: BackupCrypto only (first Dex2C target; see CHANGELOG 1.0.22).
#
# R8 minifies the release dex, so a class can only be listed here while it still
# carries its original name after shrinking. proguard-rules.pro keeps
# BackupCrypto and its member names intact via an explicit -keep rule added for
# Dex2C, therefore this line matches the shipped dex without consulting
# mapping.txt. (That keep rule is load-bearing: without it R8 renames the class
# under AGP 9.4.1 and dcc reports "no compiled methods", which the workflow
# turns into a hard error via the compiled_methods.txt assertion.)
#
# Conversion count is NOT "all methods of the class": dcc skips constructors,
# <clinit>, methods already native, and conflict methods it cannot rewrite.
# Observed on v1.3.59 release APKs (NDK 30, AGP 9.4.1, skip r8): 3 methods per
# ABI (encrypt / isEncrypted / decrypt or deriveKey). Expect this number to move
# when R8's inlining changes - it is a coverage signal, not a contract.
# Every class added here needs the same guarantee - either an existing -keep
# rule, or the R8-renamed name read back from build/outputs/mapping/release/.
Lcom/soreverse/mcp/core/BackupCrypto;
